PROJECT SCOPE AND VISION

CLAW is a hybrid AI operating environment that separates the intelligence layer (VPS) from the interface layer (Windows overlay). The vision is to provide an always-available, multi-model AI execution system with real-time observability that works even when the user's local machine is off. The system starts as a personal tool and evolves into a SaaS product. All architecture decisions must account for future multi-tenancy from day one.


RESPONSIVE AND MOBILE-FIRST UI/UX DESIGN GUIDELINES

The primary interface is the Windows overlay (desktop-first for this component). However, all React components must be built with responsive principles for future extraction to web and mobile dashboards.

Default width 380px, height 600px, resizable
Always-on-top with adjustable opacity
Dark theme with high contrast for readability
All interactive elements must have minimum 44px touch targets
Font sizes minimum 14px for body text, 12px for secondary text

Response area must support variable-height content with smooth scrolling
Permission modals must be clearly dismissible with both keyboard and mouse

SECURITY, PRIVACY, AND COMPLIANCE REQUIREMENTS

Authentication:
All API requests require Bearer token in Authorization header
Tokens are compared against hashed values in the tenants table
No API key transmission in URL parameters
Signed URLs for live view use JWT with 15-minute expiration
Telegram authentication uses allowlisted user IDs plus admin PIN

Network Security:
Phase 1-5 (Personal Use): All VPS services behind Tailscale mesh networking
Zero public ports exposed during personal use phase
All services accessible only via Tailscale IP (100.x.x.x range)
SSH accessible only via Tailscale IP, key-based auth, password auth disabled, root login disabled
xRDP for XFCE desktop accessible only via Tailscale IP, separate non-root user
OpenClaw Gateway API accessible only via Tailscale IP
noVNC live view accessible only via Tailscale IP with signed URL tokens
Redis bound to 127.0.0.1 only
PostgreSQL bound to 127.0.0.1 only
Telegram bot runs in polling mode (outbound connections only, no inbound webhook)
Tailscale handles encrypted tunneling between local machine and VPS
Future SaaS: open port 443 with HTTPS via Let's Encrypt, switch Telegram to webhook mode
xRDP and SSH remain Tailscale-only even after SaaS port opening

XFCE Remote Desktop Security:
xRDP listens only on Tailscale interface, not on public interfaces
Separate non-root user account for xRDP login
Session timeout after 30 minutes of inactivity
Used for manual VPS debugging and inspection only
Not a production workflow surface

Data Security:
All secrets stored in .env file, never committed to version control
.env.example file provided with placeholder values
Database credentials use strong passwords (32+ characters)
API keys for model providers stored in .env only
Local overlay config encrypted via Windows Credential Manager
No plaintext secrets in logs or error messages

Local Machine Security:
Every file access request from agent requires explicit user approval via overlay modal
Screenshot and clipboard access require per-session permission
No auto-grant mechanisms
Permission state resets on session end
File access scoped to specific paths, no recursive directory access without approval

Compliance (Future SaaS):
All tables include tenant_id for data isolation
Events table provides complete audit trail of all agent actions
Data deletion endpoint needed for GDPR compliance
Data export endpoint needed for GDPR portability
Consent tracking for data collection
Model name and version logged with every API call for regulatory transparency

CODE CONVENTIONS, VERSION CONTROL PRACTICES, WORKFLOWS

JavaScript and TypeScript:
TypeScript strict mode enabled in tsconfig.json
camelCase for variables, functions, and method names
PascalCase for React components, interfaces, and type aliases
UPPER_SNAKE_CASE for constants and environment variables
Async/await pattern for all asynchronous code
No use of any type without explicit justification comment
Error boundaries on all React component trees
Destructured imports preferred over namespace imports

Python:
Python 3.11+ required
snake_case for variables, functions, modules
PascalCase for class names
Type hints on all public function signatures
Docstrings on all public functions and classes
No bare except clauses, always catch specific exceptions
Pydantic models for all data transfer objects
f-strings for string formatting

SQL:
All table and column names in snake_case
All queries use parameterized placeholders, never string concatenation
Migrations numbered sequentially: 001_initial.sql, 002_add_events.sql
Every table includes created_at TIMESTAMPTZ DEFAULT now()
Every table includes tenant_id UUID with foreign key to tenants

Version Control:
Git with conventional commits: feat:, fix:, docs:, refactor:, test:, chore:
Main branch is production
Develop branch for integration
Feature branches: feature/description
Hotfix branches: hotfix/description
Squash merge to main
Tag releases with semantic versioning: v1.0.0, v1.1.0

Docker:
Dockerfile per service (gateway, workers, telegram, overlay-build)
docker-compose.yml for full stack
docker-compose.test.yml for test environment
Multi-stage builds to minimize image size
Non-root user in production containers
Health checks defined in compose file
